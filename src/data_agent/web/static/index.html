    How it works

    What happens between a question and its answer.

    From question to answer

    1. Plan. The agent reads the question and the schema and decides which tables and filters it needs.
    2. Clarify if needed. When a question could reasonably mean different things, it asks one short question instead of guessing.
    3. Explore. It looks up real column values (category names, codes, spellings) before filtering on them.
    4. Query and fix. It runs read-only SQL, reads the result, and rewrites the query when it fails or looks wrong.
    5. Check. The final query is run again before it is accepted, and every number in the answer must appear in a result the agent actually saw.

    Safeguards

    • Read-only. Only single SELECT statements are accepted, and the database is opened read-only.
    • Grounded numbers. If the answer mentions a number that no query returned, the agent gets one retry; after that the answer is withheld.
    • Data stays data. Text stored in the database is never treated as an instruction.
    • Charts come from the rows. Charts are drawn directly from the final result, never generated.

    Limits

    • Up to 8 steps and $0.05 of model usage per question; 5 seconds per query.
    • A daily budget for the whole site, and 20 questions per visitor per hour.
    • Results show the first 50 rows; a query returns at most 1,000.

    Evaluation

    The agent is measured on BIRD Mini-Dev (public SQLite databases) against a single-shot baseline, with a held-out set frozen in git before its first run. Every result, including the bad ones, is in the evaluation log.
